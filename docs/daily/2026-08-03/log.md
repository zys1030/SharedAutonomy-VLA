## 今日理解重点（15–30 分钟）

### 1. 首次抓取与失败恢复是两种数据分布

- **一句话**：正常接近—闭合和失败后重新定位—再抓取不是同一种状态转移。
- **为什么重要**：runner 在释放夹爪后通常结束 episode，数据里没有连续恢复状态。
- **本项目怎么做**：先验证首次抓取基线；恢复集另行设计。
- **代码入口**：`scripts/dry_run_cartesian_teleop.py:194-206`、`:645-685`。
- **自测问题**：为什么模型不能仅凭成功示教自动学会失败后重试？

### 2. `reset_every=25` 与移动目标响应

- **一句话**：ACT 按 chunk 播放并周期性 replan，不是每步重规划。
- **为什么重要**：目标移动后可能要到下次 replan 才修正方向。
- **本项目怎么做**：保持 `reset_every=25`，用 replan 标记核对。
- **代码入口**：`sharedautonomy/policies/act/rollout.py:145-150`、`:301-314`。
- **自测问题**：为什么目标移动后动作改变仍不等于连续跟踪？

### 3. 抓取失败要拆成 XY、Z 和恢复三类

- **一句话**：碰不到、碰错高度、碰对但恢复动作不对是不同失败。
- **为什么重要**：不能把所有失败都记成「水平偏差」。
- **本项目怎么做**：记录首次闭合 XY/Z、接触、是否重试。
- **代码入口**：`scripts/plot_grasp_close_xy.py`、`scripts/rollout_act_policy.py`。
- **自测问题**：为什么水平无偏仍可能抓不起？

### 4. 评估应优先看首次尝试

- **一句话**：反复重抓混合了首次能力与未训练的恢复行为。
- **为什么重要**：最终成功不能代表首次抓取能力。
- **本项目怎么做**：分别记 first-attempt 与 recovery success。
- **代码入口**：`scripts/rollout_act_policy.py`。
- **自测问题**：为什么不能只统计最终有没有抓起来？

## 自测参考答案

### 理解重点

1. **首次抓取与失败恢复**
   - 参考答案：示教只覆盖正常接近—闭合—放置；失败后 OOD 状态没有对应转移，模型不能凭空学会恢复。

2. **`reset_every=25`**
   - 参考答案：chunk 内先播已生成动作；目标移动后可能要等 replan 才修正，不等于连续跟踪。

3. **XY、Z 与恢复**
   - 参考答案：Z 偏低可崩开；重试引入新失败；须分开记录。

4. **首次尝试**
   - 参考答案：最终成功可能靠重试；须分 first-attempt 与 recovery。

### 面试式自测

1. **为什么没有覆盖失败后重试？** — runner 闭合后释放即结束 episode，未录恢复段。
2. **移动目标能证明什么？** — 后续观测可影响动作；不能证明 chunk 内连续跟踪或动态任务已学会。
3. **为什么不能全归因水平偏差？** — 还有偏低崩开、边缘夹飞、重试推块等。
4. **为什么不能大部分都采失败重试？** — 会扭曲训练分布，削弱首次对准稳定性。
