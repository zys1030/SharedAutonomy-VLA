# 限制与负面结果

语言：[English](limitations.md) | 简体中文

主结果是固定真机网格上的描述性对照。它能够说明这条特定数据采集与训练管线的实验表现，但不能证明 Shared Autonomy 普遍更好、确定唯一的因果机制，或代表广泛部署性能。

## 1. 评测设计限制

- 每个策略在 36 个配对条件上各评测一次，没有测量同一条件的重复性和 rollout 方差；
- 条件网格是有意选择的，不是从部署分布中随机抽样，因此比例不能解释为任意运行条件下的期望成功率；
- 两个数据集匹配 episode 数量，但因为 episode 时长不同，frame 数不匹配；
- 没有报告置信区间、统计误差线或多个训练随机种子；
- 没有通过独立 yaw-assistance 或 authority 消融来隔离辅助采集的每一种可能机制。

## 2. 真机任务范围限制

锁定评测使用：

- 一套机器人配置；
- 一个红色方块；
- 一个目标区域 `UP`；
- 一条指令；
- 固定的相机和光照条件；
- 分类 XY 位置和四个 wrap-90 yaw 值。

因此，结果不能说明策略在其他物体、目标区域、指令、连续位姿、光照、相机、机器人或部署地点上的表现。现场精确坐标只由公开的分类条件 ID 表示，有意不对外发布。

## 3. 测量与解释限制

成功和质量标记由人工观察判定，并由 rollout 视频和 replay 记录辅助。公开记录保留了标准化标签和备注，但不是自动视觉成功判定指标。

在当前网格上，Shared Autonomy 比 Manual 多恢复了一些条件，最大差异出现在远距离区域。这些只是本次实验中的诊断性关联，不能单独证明 yaw 辅助是改进的唯一原因，也不能保证同样的差异会在其他任务或训练设置中持续存在。

本锁定结果也没有与一个完整报告的经典规则基线进行横向比较。该简单任务可以用传统视觉和控制方法处理，因此不能把结果解释为“学习是必要的”。

## 4. 开发阶段的负面结果

早期开发形成了两条适合公开说明的经验：

- 带把手的 SmolVLA 路线没有达到部署门槛；
- 红黄双物体 C1 实验没有形成可靠的语言到目标物体绑定。

这些结果促使主实验转向旋转方块几何和共享控制数据质量。专项 `color_fork`、critical SmolVLA、中间训练实现和原始诊断代码继续保留在 private；公开记录只保留高层教训。

运行时可以保留可选的 post-close hold、corrective episode 等接口，但它们不是当前锁定 Manual vs Shared Autonomy 配方的一部分，不应被描述为已经启用的主线组件。

## 5. 发布与复现限制

当前代码/文档发布不包含原始 native 记录、独立的 private 视频、训练日志、模型权重、机器本地配置或 private 现场备注。导出的数据集和最终 checkpoint 托管在外部；其公开链接、许可证和 provenance 统一维护在 [`datasets.zh-CN.md`](datasets.zh-CN.md) 与 [`training.zh-CN.md`](training.zh-CN.md)，且不改变已经锁定的评测标签或汇总数字。

公开仓库只应发布经过清理的记录和可复现元数据。现场精确坐标、机器身份、本地路径、中间 checkpoint、运行时输出和污染的 legacy 快照不进入 public release。
