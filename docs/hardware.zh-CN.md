# 硬件与运行边界

语言：[English](hardware.md) | 简体中文

本文档说明 SharedAutonomy-VLA 的公开硬件平台、主机分工、时序假设和安全边界。它是系统层面的复现说明，不是针对某一台机器的现场调试手册。任务契约见 [`shape_pick_place_v1`](tasks/shape_pick_place_v1.zh-CN.md)，锁定对照见 [`results.zh-CN.md`](results.zh-CN.md)。

## 1. 公开平台

| 组件 | 公开角色 |
| --- | --- |
| RealMan RM65 系列六轴机械臂 | 机器人运动与状态反馈 |
| RealMan FAE2MR86M-B 外置串口两指夹爪 | 开合执行；第一阶段按 command-only 接口处理 |
| Intel RealSense D435i | 腕部 RGB-D 观测 |
| Logitech C920 或同类固定 RGB 相机 | 第三视角场景观测与方块 yaw 测量 |
| 3Dconnexion SpaceMouse Compact | 人工笛卡尔输入 |
| Windows 机器人主机 | 硬件访问、同步、仲裁、安全、记录和可选推理客户端 |
| 独立 Linux GPU 主机 | 训练和可选策略推理 |

当前机器人配置还可以读取腕部力/力矩信息。它描述的是末端整体 wrench，不是夹爪指尖的直接夹持力或开口反馈。

## 2. 运行时职责

Windows 主机保留安全相关的本地路径：

```text
相机与机器人状态
        → 带时间戳的观测缓存
        → 人类输入 / yaw 辅助 / 策略建议
        → 仲裁与安全过滤
        → 机器人与夹爪命令
        → episode 记录器
```

采集时，人类控制笛卡尔平移和夹爪。Shared Autonomy 额外根据第三视角相机估计方块朝向，并施加有界的局部 J6 yaw 覆盖；它不会独立执行完整任务。学习策略评测时，策略在名义控制回路中不接收人类动作，但相同的本地安全监督器仍然有效。

机器人主机记录 `human`、`assist` 和经过安全过滤的 `executed` 动作之间的区别，同时记录观测新鲜度、控制权和安全干预元数据。训练数据从这些 native episode 导出，而不是直接以策略动作格式录制。

## 3. 已验证软件环境

当前硬件检查使用以下版本：

| 层级 | 已验证值 |
| --- | --- |
| Python | 3.12.13 |
| LeRobot | 0.6.0 |
| RealMan SDK | `Robotic-Arm` 1.1.5 |
| RealSense SDK binding | `pyrealsense2` 2.56.5.9235 |
| SpaceMouse HID 访问 | `hidapi` 0.15.0 |

硬件 SDK 必须 lazy import。没有机械臂、相机、夹爪或 SpaceMouse 时，离线 import、单元测试和 dry-run 工具仍应可用。

## 4. 时序与新鲜度假设

公开运行点如下：

| 路径 | 运行点 | 解释 |
| --- | ---: | --- |
| 腕部 RGB-D 与固定 RGB | 约 640 × 480、30 FPS | 观测来源；逐帧检查新鲜度 |
| 机器人 realtime state push | 当前验证配置约 200 Hz | 反馈来源；缓存最新状态 |
| SpaceMouse 原始 HID report | 约 125 Hz | 平移与旋转 report 交替到达，完整 6-DoF 状态刷新更慢 |
| 采集命令路径 | 默认 10 Hz、低跟随 CAN-FD | 第一阶段的保守运行点 |
| 处理/同步循环 | 部分组件使用 nominal 50 Hz 调度 | 不表示采集命令路径必须运行在 50 Hz |

这些是实测或选定的软件运行点，不是硬实时保证。运行时使用主机 monotonic 时间戳，并记录 `frame_age`、`state_age` 和输入年龄。观测或输入过期时，必须按照相应安全策略保持、输出零动作或拒绝命令；不能只用平均吞吐量判断数据新鲜度。

已验证的相机和机器人链路仍存在调度与传输长尾。因此项目不声称在通用 Windows 主机上能够稳定实现 100 Hz 或 200 Hz 的端到端闭环控制。

## 5. 安全边界

物理运动默认关闭。允许执行运动的运行必须同时满足：

- 已打开显式 runtime motion gate，并提供有效本机配置；
- 操作者在场且具有可用的急停路径；
- 先完成只读设备检查和数据流检查；
- 启用关节、工作区、速度、加速度、步长和新鲜度检查；
- 人工采集时启用 deadman 和夹爪状态检查；
- 输入丢失、状态过期、安全拒绝、异常或操作者松手时能够安全停止。

安全监督器位于机器人主机本地，处于人类或策略建议与物理机械臂之间。dry-run 或 SDK 连通性检查通过，不等于获得运动授权。硬件调试和任何运动测试都必须遵循单独的操作者控制流程。

## 6. 硬件接口边界

第一阶段使用 RealMan FAE2MR86M-B，并将其视为 command-only 设备。软件记录命令行程和时间，但不伪造实际开口、位置、电流或夹持力反馈。在真实反馈路径得到验证前，完全张开和完全闭合是可靠的公开状态。

腕部力/力矩传感器可以支持后续接触检测或力控工作，但其读数需要工具和重力标定。没有任务专用模型与验证时，不能把它解释为指尖夹持力。

固定第三视角相机必须覆盖拾取区和命名目标区域。支架移动、碰撞、USB 拓扑变化或重新安装后，需要重新检查视野和同步；腕部相机重新安装后，需要重新验证手眼关系。

## 7. 公开与私有边界

公开版本可以描述硬件类别、传感器角色、软件版本、时序假设、安全行为和汇总后的联调结论。

以下内容保留在本机或私有文档中：

- 控制器 IP、序列号、USB index 和端口分配；
- 标定矩阵、相机内参和设备专属 profile；
- 精确工作区多边形、桌面几何、任务场地坐标和 ready pose；
- 夹爪标定、偏置和本机运动限制；
- 原始联调日志和机器本地路径。

这些值应通过本机配置或环境专属部署备注提供，不应复制进公开任务或硬件契约。

## 8. 复现入口

仓库将硬件访问、dry-run 验证、观测同步、安全过滤和 episode 记录分成独立路径。建议按以下顺序使用：

1. 无硬件完成 import 和 schema 检查；
2. 进行只读设备与观测检查；
3. 进行安全、IK、工作区和新鲜度 dry-run；
4. 在操作者控制下进行低速硬件联调；
5. 最后才进行任务采集或闭环评测。

公开评测协议和任务条件维护在 [`results.json`](results.json) 与 [`evaluation_records.csv`](evaluation_records.csv) 中。详细机器联调记录有意与本公开系统说明分开维护。

有代表性的只读检查、benchmark 和带显式门控的运动验证工具见 [`tools/hardware/README.zh-CN.md`](../tools/hardware/README.zh-CN.md)。
