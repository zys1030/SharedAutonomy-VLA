# 每日计划与工作日志

`docs/daily/` 用于管理每天的执行清单和历史记录。每个工作日使用一个 ISO 日期目录：

```text
docs/daily/YYYY-MM-DD/
├── plan.md
└── log.md
```

## 何时使用本文档

**人类协作者**：开始当天有实质内容的工作前阅读；收工前整理 log。

**AI / Agent**：仅在以下情况阅读 daily 相关文档——

- 用户要求安排当天任务或创建 `plan.md`；
- 用户要求收尾整理、更新 `log.md`；
- 用户明确 `@` 了当天 `plan.md` 或 `log.md`。

日常代码改动、问答、评审**不必**预读 roadmap 或上一日 log。

## 文档职责

- `plan.md`：当天任务状态的唯一来源，开始工作前创建，工作中持续勾选；
- `log.md`：当天实际发生事项的历史记录，收工前整理；
- [`../roadmap.md`](../roadmap.md)：阶段级目标和验收标准；
- [`../overview.md`](../overview.md)：长期稳定的项目背景与系统设计；
- [`../datasets.md`](../datasets.md)：native 采集池与 LeRobot 快照清单（export / 扩量后同步）；
- [`../hardware_setup.md`](../hardware_setup.md)、[`../decisions/`](../decisions/)：长期有效的技术事实和设计决策。

## 每日流程

1. 从 [`templates/plan.md`](templates/plan.md) 创建当天 `plan.md`；
2. 参考上一工作日 `log.md` 的“下一工作日建议”，确定当天范围；
3. 工作过程中勾选任务，并记录延期、取消或阻塞原因；
4. 收工前从 [`templates/log.md`](templates/log.md) 创建当天 `log.md`；
5. 用 15–30 分钟撰写日志中的 **「今日理解重点」**（默认 3–5 条；轻量日可精简到 2–3 条，但不可整节省略）；
6. 将可长期复用的结论同步到对应主题文档，日志只保留摘要和链接；若当日有 export / 阶段性扩采 / 新训练 job，同步更新 [`../datasets.md`](../datasets.md)；
7. 在日志末尾写下一工作日候选任务。

## 维护规则

- 未完成任务必须标记为延期、取消或阻塞，不能直接从记录中删除；
- 日志完成后原则上不重写历史，只修正明确的事实错误；
- “下一工作日建议”不是正式承诺，下一天的 `plan.md` 才是正式清单；
- **「今日理解重点」为收工默认项**：每天 log 必须包含该节（见 [`templates/log.md`](templates/log.md)）；通常 3–5 条，轻量日可 2–3 条，但不可省略整节；
- 每个理解重点尽量附代码入口和一个自测问题；**完整参考答案写在 log 文末「自测参考答案」**（理解重点与面试式自测均可），正文只保留问题以便先自测；
- 测试原始输出、高频控制数据和 episode 数据不写入 Markdown 日志；
- 真实 IP、相机序列号、标定矩阵等机器本地信息仍只保存在 `configs/local/`。
