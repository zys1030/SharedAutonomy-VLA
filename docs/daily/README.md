# 每日计划与工作日志

`docs/daily/` 用于管理每天的执行清单和历史记录。每个工作日使用一个 ISO 日期目录：

```text
docs/daily/YYYY-MM-DD/
├── plan.md
└── log.md
```

## 文档职责

- `plan.md`：当天任务状态的唯一来源，开始工作前创建，工作中持续勾选；
- `log.md`：当天实际发生事项的历史记录，收工前整理；
- [`../roadmap.md`](../roadmap.md)：阶段级目标和验收标准；
- [`../hardware_setup.md`](../hardware_setup.md)、[`../decisions/`](../decisions/) 等：长期有效的技术事实和设计决策。

## 每日流程

1. 从 [`templates/plan.md`](templates/plan.md) 创建当天 `plan.md`；
2. 参考上一工作日 `log.md` 的“下一工作日建议”，确定当天范围；
3. 工作过程中勾选任务，并记录延期、取消或阻塞原因；
4. 收工前从 [`templates/log.md`](templates/log.md) 创建当天 `log.md`；
5. 用 15–30 分钟整理并理解日志中的“今日理解重点”；
6. 将可长期复用的结论同步到对应主题文档，日志只保留摘要和链接；
7. 在日志末尾写下一工作日候选任务。

## 维护规则

- 未完成任务必须标记为延期、取消或阻塞，不能直接从记录中删除；
- 日志完成后原则上不重写历史，只修正明确的事实错误；
- “下一工作日建议”不是正式承诺，下一天的 `plan.md` 才是正式清单；
- “今日理解重点”只保留 3–5 个关键概念，重点解释为什么这样设计，而不是复述全部改动；
- 每个理解重点尽量附代码入口和一个自测问题，确保可以脱离 Codex 说明清楚；
- 测试原始输出、高频控制数据和 episode 数据不写入 Markdown 日志；
- 真实 IP、相机序列号、标定矩阵等机器本地信息仍只保存在 `configs/local/`。
